# Content scope and product memory — November 7, 2026

Party games previously started at ten core pages, while the form already accepted larger counts. Ten was not a universal product limit. The new recommendation separates suggested scope from the actual selected scope, explains the sample-based rationale and counts core content apart from covers, answer keys and support pages. A seller-entered count wins; otherwise Studio adopts the fresh recommendation. Final effective counts propagate to the visible form and saved workspace. Invalid fractional/out-of-range counts fail validation; calendar, ABC, resume, slides and existing artwork/icon limits now share the same effective-count normalization used by prompts, listings and QA. More pages are not presented as evidence of more sales.

The protected research preview now returns a product recommendation with observed features, scope, a concrete creative direction and prior related products. Preparing a package carries the direction into the files brief and an original-content/no-count-inflation/QA requirement into the master prompt. Existing research supplies source IDs, price anchors, tags and authoritative listing metadata. This is a design hypothesis; the app does not prove a globally best product, creative originality or a sales advantage.

Successful researched packages record their kind, topic, name, title, creative direction, scope and preparation state. Product memory also reads existing saved digital products and Etsy-bound records, without treating an Etsy record as verified publication. It retains up to 300 memory records and inspects up to 200 indexed saved products (up to 400 distinct combined rows). Automatic category selection excludes previously prepared/saved topic keys and up to 120 prior suggestions, compares close-scoring fresh alternatives with recent subjects across categories, and can expand candidates from observed compatible tags. Token-order/format/plural normalization prevents simple renamed-query repeats; it is not a semantic or file-content plagiarism detector.

If available category candidates are exhausted, auto-selection stops with a visible instruction to choose a new subject instead of recycling the first result. Explicit seller queries remain available for review and revision. Related prior packages appear in the recommendation; after the three supported creative approaches for that topic have been prepared, a new package requires a new topic rather than cycling the same approaches. Existing saved work can still be resumed. History is bounded and uses KV reads/writes; it is not an atomic cross-worker concurrency lock or an infinite no-repeat guarantee.

New research invalidates the older shareable package until preparation runs again. Response guards prevent late research/generation from overwriting newer form changes or resumed work. Counts are core content units, not guaranteed distinct games; an escape room may span several core pages for one linked puzzle sequence.
