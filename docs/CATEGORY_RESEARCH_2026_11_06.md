# Product-specific research before listing preparation — November 6, 2026

## Problem and resulting behavior

Category auto-pick ranked cached searches but repeatedly fell back to the first catalog entry without adequate measured evidence. The printable form also discarded the seed's competition/strategy when rendering its initial state, so the seller could see a repeated query without its sources. Some categories had only one or two starting queries. A search query was easy to mistake for the final listing title.

All 19 supported digital kinds now have at least three distinct research starting points. With configured Etsy access, auto-pick probes at most three searches per request, reuses appropriately fresh caches, compares available evidence and explores unmeasured alternatives. Rate limiting stops the batch. Missing/failed/stale samples are labeled and do not receive invented scores. Recent choices and an explicit previous-query exclusion diversify later picks. This compares observed search samples, not all of Etsy and not verified bestseller sales. Sellers' explicit product queries are preserved.

Studio shows category alternatives, initial source-backed strategy and comparisons before a listing package exists. Goxi's first action calls the protected, read-only POST /api/printables/research endpoint for the actual product kind/topic. It creates no product name, listing, handoff or draft. The report shows comparable sources, price anchors, observed features, evidence IDs and limitations. A second Goxi action prepares the listing package, with fresh product-specific research again. Editing the product/query/reference links invalidates the old preview; stale in-flight results cannot replace a newer generation or resumed workspace.

Sellers can paste up to five Etsy listing links/IDs, including recommendations or listings they saw labeled as bestsellers. The app fetches the selected sources, checks active/digital/topic/kind compatibility and keeps eligible seller-selected rows visibly marked even when they have low favorites. It does not automatically scrape Etsy recommendation panels, verify bestseller badges or obtain hidden unit sales/conversion data. Source observations do not establish why a competitor sold.

Production instructions carry quoted source IDs/titles/URLs/prices, observed-feature actions and an original-execution requirement. Party-game research prioritizes applicable answer-key/user-guide observations. The instructions require original questions/artwork/layouts, no copying of competitor material, file-level QA for differentiation choices and consistency with the authoritative product spec. Only final, actually delivered features may be promised in the listing. A prompt requirement is not proof that an external assistant has produced a better product or a future sales improvement.

## Validation

320 automated tests passed, zero failures. The 25 added tests include every supported digital kind, bounded category probes, alternate-query selection, missing data, 429 stop, exact-query preservation, distinct subject-specific party titles, selected low-favorite sources, read-only preview authorization/no writes, preview-to-package source transfer and real component invalidation. The existing full Worker/UI path still covers file upload and draft transfer. Root/mobile TypeScript checks, browser build and Android Expo export passed.

Actual private-browser QA used shared App.tsx and Worker code with explicitly synthetic Etsy responses. Party selection showed family-game-night, birthday and escape-room alternatives with three measured test samples; another-query selection changed the previous query. An explicit birthday query produced a product-matched report with 30 sample rows before any listing package. A selected sample source was marked, then retained in the generated birthday listing and the 36,923-character outgoing package. DOM inspection confirmed the package contained the selected source, ORIGINAL EXECUTION, no-copy instructions and a prohibition on inventing why a competitor sold. No real listing was published, no assistant message was delivered and no product files were generated by an external assistant in this check.

The hosted bundle initially reported a dynamic-module fetch failure immediately after deployment; one reload recovered and the interactive checks then completed. This did not establish a device-side failure. Actual Android installation, live Etsy account evidence, external ChatGPT/Claude output quality and real sales performance remain separate unverified checks.
